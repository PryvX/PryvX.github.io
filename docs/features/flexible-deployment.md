# Flexible Deployment

PryvX's infrastructure is cloud-agnostic and supports both centralized and federated on-premise deployment models, so participants are never forced onto a single cloud provider or operating model to join a collaboration.

## Cloud-agnostic by design

Because PryvX's confidential clean rooms are built on standard confidential-computing primitives (TEEs and remote attestation) available across AWS, Google Cloud, Azure, and on-premise hardware, the same workload can run wherever a participant's data already lives, without redesigning the computation.

## Deployment options at a glance

- **Centralized** — PryvX operates the clean room infrastructure for you.
- **Federated** — each participant runs its own PryvX node inside its own infrastructure.
- **Hybrid** — a mix of centralized and federated participants inside the same workspace.

Full detail, including a comparison table, is in [Deployment Models](/overview/deployment-models).

## Why it matters for regulated industries

Banks and government agencies frequently operate under data residency and infrastructure-ownership requirements that rule out a purely centralized SaaS model. Flexible deployment lets PryvX meet those requirements without fragmenting the collaboration — a federated bank and a centralized fintech partner can still run a joint computation inside the same contract and the same audit trail.
