# Verifying Computation Integrity

Every completed computation produces an attestation log that any workspace participant can independently verify — you do not need to trust PryvX's report of what happened; you can check the underlying evidence yourself.

## What the attestation log contains

- The cryptographic identity (measurement hash) of the exact code that ran inside the confidential clean room.
- Proof that this code ran on genuine, unmodified TEE hardware, generated by the hardware's remote attestation mechanism — see [Confidential Clean Rooms](/overview/confidential-clean-rooms).
- The contract version the run was bound to, and confirmation that the run's inputs and outputs matched that contract's declared scope.
- A confirmation that intermediate state was scrubbed at job completion, with no residual data retained.

## Steps to verify

1. From the completed analysis, select **View Attestation Log**.
2. Compare the reported code measurement hash against the published, versioned hash for the PryvX clean room image used for this computation type. Matching hashes confirm no unauthorized code substitution occurred.
3. Confirm the attestation signature validates against the hardware vendor's root of trust (Intel, AMD, Arm, or NVIDIA, depending on the TEE used).
4. Confirm the contract version referenced in the log matches the contract you expect this run to have used.

## Why this matters for regulated participants

For institutions that must demonstrate to a regulator or internal audit function that a decision was made appropriately, the attestation log — not PryvX's word alone — is the evidence. It is retained as part of the [audit trail](/how-to-guide/exporting-insights/audit-trail-and-compliance-logs) for as long as your workspace's retention policy specifies.
